# Oxlint diagnostic qualification pilot

Run `npm run check lint` after frozen root `npm ci`. The explicit class uses existing admission, process ownership and producer/source/log validation. ESLint and default Node/browser/orchestration coverage remain unchanged.

Official Oxlint 1.80.0 and exact-version bindings install only into an owned attempt, with frozen SHA-512 lock integrity, scripts disabled, owned configs/cache, installed version and native architecture/digest checks. Trial platforms: Darwin arm64 and GNU Linux x64. No global software, shared/editor hook, product configuration or unrelated formatting changes. Native-release bootstrap and type-aware qualification remain separate tracks.

Fourteen copied/seeded inputs exercise all six shadcn policies, isolated violations, CSS custom properties, typo guidance, UI exemptions, Unicode and CRLF. The tracked unknown-class regression extends the five original assertions. Candidate rules/settings are generated from resolved ESLint configuration per input; added rules or settings changes fail visibly. No native ESLint rules are active here, so no native-rule replacement is claimed.

Both engines must accept clean inputs with zero diagnostics/zero exit and reject invalid inputs with matching error exit. Three pairs compare complete rule/severity/range/message/repair-text multisets and duplicate counts. UTF-8 byte ranges convert to UTF-16 with boundary checks. UI exemptions and the other three active UI policies are exercised. Parser-failure controls require exit 1 plus the pinned engine’s genuine parser diagnostic bound to the broken input; crashes, configuration errors, unrelated stderr and other diagnostics fail qualification; equivalent parser messages, autofix/suggestion payloads, type-aware lint and arbitrary repository inputs are unqualified.

`oxlint-qualification/v1` records resolved policies, tools/package/lock/native/corpus digests, diagnostics, per-command logs/rusage and source. Its parent `factory-verification/v1` binds producing command, whole source and captured log. Linux uses the existing qualification job. Uploaded artifacts include receipts, inputs/config, normalized diagnostics and logs/resources; dependency links and tool caches are excluded.

Each observation starts a process. First/repeated runs do not flush host or upstream caches and do not establish hardware cold/warm behavior. Wall includes supervision; RSS uses independent OS-time reports and Linux KiB conversion. Native pool stays at two. Three pairs on a host are bounded evidence, not repository-wide speedup or adoption. ESLint remains pending independent review and required green checks.

Sources: [official JS-plugin support](https://oxc.rs/docs/guide/usage/linter/js-plugins.html) (currently alpha), [pinned release](https://github.com/oxc-project/oxc/releases/tag/oxlint_v1.80.0), [official npm metadata](https://registry.npmjs.org/oxlint/1.80.0).
