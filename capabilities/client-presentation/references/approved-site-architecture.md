# Approved browser presentation architecture

The baseline is five mutually exclusive views in this order: Home, Purchases, Tour List, Demographics, Sources. Leases appear when lease records exist. Strategy is optional for explicit 30/70 ownership and is omitted for full practice occupancy and lease-only briefs. The fixed sanitized shell contains synthetic records only.

The approved visual shell is a centered white page up to 1120px on a pale blue outer background. CARR/client branding sits at the left of the sticky masthead, with bold pill navigation at the right. The current-page heading uses navy Oswald type and an orange underline inside the page. CARR logos link to carr.us. Client logos retain approved colors and provenance. Home places the brand/headline and market story at the left of a desktop hero, with the development map at the right; the hero stacks on phones. Three sourced statistic tiles use pale blue fills and orange top borders. Each tile links to the detailed demographic research. Image development cards follow, then one next action to the configured purchase or lease options. Home has an overview only; population and income charts remain on Demographics. Development cards show their own hover affordance and open a sourced project dialog. Home has no development table, duplicate floating popup or explainer beneath the map.

Purchases contains a numbered locator, sourced practice-screening criteria and two-column image card grid on desktop, stacking on phones. Four options form two rows of two. Addresses, cards and map markers open the shared property detail dialog. The dialog includes the complete supplied description, labeled facts, planning/availability notes, source conflicts, supplied floor plan, source attribution and Add/Remove control. A bottom Start Tour List action advances the review. There are no purchase/lease summary tables, dedicated property pages or listing-agent/listing links.

Tour List places Available on the left and Selected on the right on desktop and stacks the columns on phones. A visible animated drag handle moves a property between the two columns; Add/Remove remain usable by touch and keyboard. Selected properties each have Notes for CARR. There is no client-managed ordering or global notes box. Server integration may preserve a legacy notes field in the transport, but it is not a visible global client input. Shared selections and property notes use the same versioned save. Loading, saved, saving, error and conflict states are truthful, and an acknowledged save survives reload.

One validated demographic model owns geography, research dates, per-measure units/period/source, chronological population counts, age cells and labeled household-income cells. Counts determine totals, shares, charts and threshold bands. Age counts reconcile to the latest population at the same period. The income median explicitly binds the distribution's source and period. Cell bounds are lower-inclusive and upper-exclusive. Cards use natural heights so grid gaps cannot create overlaps; freshness derives from validity dates rather than a cached status.

MapLibre locators fit all sourced coordinates, including optional current-practice context. Colliding labels move with visible stems to their original coordinate. Unpinned records remain in cards. Locators are approximate context, not entrances or navigation destinations. The default visual map context uses pale blue land, white roads with blue-gray casing and blue water. Image previews on marker hover/focus lead to the same full dialog; card hover never adds a duplicate popup. Synthetic geometry exercises this composition without client GIS data. Real source layers, provider styles and rights belong to the destination's reviewed map configuration.

An explicitly configured 30/70 page preserves the approved four numbered stages: practice/outside-tenant allocation and rent-versus-loan coverage across properties; side-by-side property metrics with What Stands Out image previews; separate practice buildout and tenant TI, practice rent avoided and annual lease-up/mortgage contribution; and the holding-year line/slider, final-year equity components and ownership-versus-leasing summary. Tenant TI controls appear with buildout and the ownership summary and stay synchronized. Every numeric comparison derives from the same financial model and configured assumptions. The fixed synthetic example exercises the 25/50/75 controls and ten-year component view; those values are example configuration, not lending or CARR domain policy.

Lease and 30/70 fixtures prove these capabilities remain available without changing the five-page baseline. Browser acceptance covers desktop/mobile, marker hit targets and collision negatives, sticky headings, dialogs and focus return, grid shape, drag and Add fallback, per-property note persistence, service failure/conflict, demographic layout and reduced motion.
