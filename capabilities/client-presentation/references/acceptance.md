# Browser acceptance

Before changing or publishing a presentation, bind the approved prior source/version and compare the actual desktop/mobile layout with the result. The fixed sanitized shell is the default; preserve an explicitly supplied approved design. Check the centered white page and pale outer background, CARR/client branding at left with pill navigation at right, navy Oswald sticky title with an orange underline, Home headline/map hero, three linked demographic statistic tiles before image development cards. Reusing colors alone does not establish template fidelity. Record the compared source, differences and resulting screenshots in private delivery evidence; never copy client facts or assets into the public factory. If the approved reference is unavailable, report the missing reference before claiming fidelity.

Review only features applicable to the current brief; omitted optional tools are not defects. Check visible prose on Home, options, dialogs, Demographics and Sources for factual presentation rather than interface narration or generic homework. Retain source uncertainty, functional labels and genuine status messages. Confirm supplied properties and additional research candidates stay distinct wherever they appear.

For configured maps, compare the actual basemap, palette and interaction with the approved reference. Reconcile each project card with its expected marker or an explicit source limitation; a working map with one marker does not establish coverage of a multi-project page. Exercise every marker's matching dialog on desktop and mobile, including after changing views. Markers must remain clear of controls and attribution; displaced labels retain stems to their geographic anchor. Approximate context markers must not imply surveyed boundaries, construction footprints or completed roads.

When a comparison tool is configured, inspect its first-load numerical result and basis label. Exercise presets, sliders or other applicable controls, monthly-to-annual conversions where offered, input clearing and reset behavior. Check that visual differences and exact values update together, unknown quotes and ranges remain distinct, and expense structures stay labeled. Judge the actual result and interaction, not merely the existence of a calculator. These checks do not require adding an otherwise irrelevant comparison feature.

`npm run check presentation` executes the pinned Playwright/Chromium suite against synthetic full occupancy, 30/70 and lease-only packages. CI installs Chromium before the repository check. Tests use the real MapLibre renderer with an inline synthetic roads/water style and visibly colored synthetic building images, so external tiles, fonts or credentials are not needed for fixture qualification.

The suite verifies configured navigation, one visible view, the Home demographic snapshot/link and next action, sourced purchase screening and Tour List next action, all four optional 30/70 stages: allocation/rent coverage, property metrics and image previews, separate practice buildout/TI and annual carry, and holding-period/ownership-versus-leasing comparisons with synchronized TI controls, two-column desktop and stacked mobile grids, sticky headings, marker bounds/visibility/hit targets, detail dialogs and Escape focus return, Add/Remove, drag between columns, Notes for CARR, save/reload persistence, version conflicts, unavailable service behavior, demographic card bounds and reduced motion. Every supplied card and dialog image must load with visible dimensions; synthetic pixel coverage rejects a blank image. Map image previews and coincident stems retain the original geographic anchor. Negative controls hide a marker, overlap two markers and replace a supplied image with white pixels; the same assertions must reject each fault. Demographic tests reject mismatched units, periods, sources, overlapping income cells, stale dates and divergent totals.

`PRESENTATION_SCREENSHOTS` names a private external directory for screenshots, including separate 30/70 stage panels so long mobile pages remain reviewable. Compare Home, options, dialogs, map previews and all configured strategy stages to the approved source; a Home screenshot alone cannot establish fidelity. Browser fixtures use a synthetic same-origin selection service. Passing them does not prove deployed authentication, database persistence, provider rights or a client's researched data.

The destination product runs browser acceptance on the generated package and records its version and package digest with hosted observations of anonymous rejection, authenticated access, and save/reload/conflict behavior. Missing hosted evidence leaves deployment, authentication and persistence unverified. Preserve the established or request-bound client portal host/path and verify that exact human-facing URL, including `share.doctorcre.com/<client>/` when applicable; a provider URL is insufficient. Review the client's actual site on the intended devices and verify its assets and source facts before sharing.
