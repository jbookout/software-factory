# Browser acceptance

`npm run check presentation` executes the pinned Playwright/Chromium suite against synthetic full occupancy, 30/70 and lease-only packages. CI installs Chromium before the repository check. Tests use the real MapLibre renderer with an empty inline style and local synthetic images, so external tiles, fonts or credentials are not needed for fixture qualification.

The suite verifies configured navigation, one visible view, the Home demographic snapshot/link and next action, sourced purchase screening and Tour List next action, explicit 30/70 TI/property/year/line controls, two-column desktop and stacked mobile grids, sticky headings, marker bounds/visibility/hit targets, detail dialogs and Escape focus return, Add/Remove, drag between columns, Notes for CARR, save/reload persistence, version conflicts, unavailable service behavior, demographic card bounds and reduced motion. Negative controls hide a marker and overlap two markers; the same assertions must reject both faults. Demographic tests reject mismatched units, periods, sources, overlapping income cells, stale dates and divergent totals.

`PRESENTATION_SCREENSHOTS` names a private external directory for screenshots. Qualification fixtures use a synthetic same-origin selection service; their receipt labels that adapter explicitly. Passing them does not prove deployed authentication, database persistence, provider rights or a client's researched data.

The publication helper runs browser acceptance on the generated package. The destination product supplies hosted observations that bind its version and the package digest, anonymous rejection/authenticated access, and save/reload/conflict results. Missing hosted evidence leaves the receipt undeployed and unverified. Review the client's actual site on the intended devices and verify its assets and source facts before sharing.
