# Factory Design Journal

Slice 5 supplies `software-factory/design-journal`: private SQLite records and
digest-addressed files, with JSON-shaped commands for slice 7's authenticated MCP
core. It installs no server, selects no host and accesses no CARR/product store.

```text
trusted host scope (user / project / version)
                    |
            journal.execute(command)
                    |
       existing interview + record validation
                    |
    SQLite revision / event / record transaction
                    |
     registered digest-addressed artifact bytes
                    |
        scoped backup → verified new-root restore
```

## Scope and commands

`openDesignJournal({ userId, projectId, version, root? })` returns `execute` and
`readArtifact`. The host authenticates its caller and selects an authorized scope
before opening the handle. Identity fields on commands are rejected. A supplied
identity is not authentication; transport and reviewer-seat authentication remain
slice 7/4 responsibilities.

The default root is `~/.local/share/software-factory/design-manager/`, containing
`journal.sqlite`, `database-identity.json` and `artifacts/`. Python 3.11 or newer
with [SQLite deserialization support](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.deserialize) and a POSIX local filesystem are
required. Standard-library SQLite preserves the factory's Node 20 minimum without
new runtime npm dependencies. The adapter checks restore capability before opening
a store. Direct database/file mutation is unsupported.

| Command | Input beyond `command` | Result |
| --- | --- | --- |
| `read` | none | revision, interview projection, records/events, reported-only authority and host blocker |
| `archive` | base64 `bytes`, explicit `origin` | registered artifact ref/digest |
| `append` | `kind`, `record` | immutable record ID |
| `start-interview` | exact `sourceRevision` | persisted interview and first question |
| `answer-interview` | one `response` | persisted answer before returning the next question |
| `propose-scope` | one `proposal` | persisted proposal and pending scope decision |
| `reassess-layer` | one `assessment` | persisted dependency reassessment |
| `backup` | private new `destination` | completed scoped snapshot receipt |

Every mutation requires `expectedRevision` and `idempotencyKey`. Exact retries
return the original receipt after restart. Changed content on the same key fails.
Stale revisions require rereading. Revisions include archives. Interview commands
use the existing pure interface, accept no replacement trace/projection and bind
the version answer to the handle. Scope expansion retains its explicit decision,
criterion, assurance and reassessment protocol. Appends cannot alter interview
scope, lifecycle or acceptance authority.

Record kinds are `reference`, `decision`, `gate`, `worker-receipt` and `evidence`.
Gate/handoff records retain slice-1 schemas as **reported history**. Evidence must
satisfy `design-check.v1` and bind this project/version; older incomplete proof
shapes cannot enter that kind. Storing a pass authenticates no reviewer and advances
no gate. Slice 4's evaluator remains responsible for verdicts.

## References and artifact provenance

`design-reference.v1` retains source URL/author/revision, source/inspection dates,
availability, label/origin, platform/viewport/state, observed property, inference,
user decision, borrowed property, adaptation, mismatch, rejection test, reviewer
outcome, limits, reuse status and experiment history. Rejected experiments require
their failed property and replacement. Missing access requires an unverified
claim. Source revision may be null; dates must be valid.

| Label | Permitted observed claim (or `unverified`) |
| --- | --- |
| still | appearance |
| recording | bounded transition |
| live | exercised behavior |
| inspected-source | implementation facts |
| vendor-claim | attributed claim |

Generated/reconstructed material retains its origin and supports only appearance
or unverified claims. No label approves a target build. Validation constrains
declared provenance; it does not authenticate a capture or prove its observation.
Copied code/assets require retained license and exact reuse permission. No external
source is fetched by the journal.

Archive nonempty bytes before referencing them, at most 1 MiB each. Origin is
explicit: `captured`, `generated`, `reconstructed` or `unspecified`. Origin is
immutable within the scope; a later reference cannot turn generated bytes into a
live capture. Use `unspecified` for non-reference evidence pending classification.

Refs are `sha256:<hex>` with bare-hex digests, matching slice 4. Slice-1 interview
and handoff fields require the same digest with a `sha256:` prefix. The reader
checks registered scope, private regular files and matching bytes. Traversal,
symlinks, hard links and substitution fail. Digests bind bytes, not authority.

## Transactions and restore

Migration version 1 partitions users/projects/versions, enforces unique IDs/keys
and prevents updates/deletions of event, record and artifact registrations.
A host directory lock serializes file operations with SQLite transactions.
After acquiring it, the adapter rechecks directory identity and privacy and
accesses files relative to that locked directory. First-time initialization
creates a database identity seal; reopening requires the same database file.
Missing or replaced databases refuse reads and retries instead of resetting
history. Restore creates a new seal for the new root.
Concurrent writers at one revision produce one commit and one conflict. Answers
and projections commit with their events. Archive events retain digest/origin
rather than duplicating binary bytes in SQLite. Archives write to unique temporary
files, verify and sync complete bytes, then atomically publish the digest filename
before registration. Interrupted temporary files cannot block identical retries
and are excluded from scoped backups.

Roots/directories are user-owned mode 700, databases mode 600, artifacts mode 400.
State and snapshots must be outside every Git checkout, including worktrees and
symlinked checkout parents. Handles pin root identity. These checks detect
unsupported tampering; another process as the same OS user can alter files.

`backup` snapshots only the handle's scope, including rejected records, pending
interviews and registered bytes. It verifies history and digests before creating
the destination. A completion manifest binds scope, database bytes and the full
artifact list, and is written last. An interrupted snapshot cannot restore.

`restoreDesignJournal({ root, backupRoot, userId, projectId, version })` verifies
the snapshot before creating a **new** private root. It compares records,
registrations and interview projection against event history; a lost rejected
record cannot be concealed by updating the database checksum. Existing roots and
cross-scope imports fail. Restore captures caller options before awaiting inspection
and requires the inspected database digest at installation. Validation reads the
captured database bytes, so a changed snapshot refuses before creating a target.
Checksums detect drift, not backup-author identity.

After interruption, reread and retry the same mutation/key to establish whether
it committed. Do not invent a new key for an unknown outcome. A rolled-back
archive can leave an unreferenced blob; no destructive cleanup is installed.
An interrupted restore's partial destination is refused on retry; use a new root
with the same verified backup. Mutation metadata is limited to 1 MiB of UTF-8 JSON;
archive binary bytes have their separate 1 MiB limit. Before committing, the
adapter checks proposed database pages against 16 MiB and complete projections
against the 16 MiB transport budget, reserving space for restore inspection.
Exceedance rolls back, preserving read, exact retry and backup access to accepted
history across all scopes.

## Qualification and removal

`npm test` runs `test/acceptance/design-journal.test.mjs` against actual SQLite and
files for synthetic task/catalog scopes: all labels, cleanup/restart/restore,
rejected experiments, provenance omissions, substitution, generated-origin
promotion, conflicts, isolation and private-path failures. It also covers size
budgets, lock-wait/path replacement, database loss, process-death archive recovery,
restore input/snapshot mutation, scope acceptance/decline, dependency reassessment,
interview versions, evidence binding and inspection dates. A strict TypeScript
consumer compilation checks accepted and rejected command shapes in this suite.

Every state exposes this tested blocker: **Joe must choose the persistent factory
host and authorize cost; laptop-off qualification remains required**. Local restore
does not qualify a Mac-independent host, backup schedule or cloud integration.
No login, purchase, hosting install or publication occurs here.

Remove the package export, adjacent journal modules/schema and acceptance test to
retire the pilot. Private journals/backups remain SQLite and digest-addressed
files; products have no runtime dependency on the journal.
